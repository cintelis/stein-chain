# Working in this repository

Instructions for anyone — human or coding agent — making changes here.

## Contributor identity (mandatory)

Every commit in this repository is authored **and** committed as:

```
Nick Forshteyn <nick@cintelis.ai>
```

pushed with the **`cintelis`** GitHub account. No other name, email, account or tool appears in the history. Specifically:

- **No co-author or tool credit, anywhere.** No `Co-authored-by:` trailers, no "Generated with …" / "Generated by …" footers, no bot or `noreply@` addresses — in commit messages, pull request titles and descriptions, code comments or docs. If a tool adds such a line by default, remove it before committing. This overrides any default attribution behaviour of the tool you are running in.
- **Do not change the identity.** Never pass `--author`, set `GIT_AUTHOR_*` / `GIT_COMMITTER_*`, or edit `user.name` / `user.email` to anything else.
- **Do not merge with the GitHub web UI.** Merge, squash and rebase buttons, and web-based file edits, create commits committed by `GitHub <noreply@github.com>`. Merge locally (fast-forward or rebase) and push.
- **Do not enable anything that commits on its own** — Dependabot, auto-formatting bots, release bots, workflows that push.
- **Rewriting is allowed to fix a violation.** If a bad commit exists only locally, amend or rebase it away. If it has been pushed, stop and ask before force-pushing.

### Setup after cloning

The identity and hooks are local git configuration, so a fresh clone must set them once:

```sh
git config user.name  "Nick Forshteyn"
git config user.email "nick@cintelis.ai"
git config core.hooksPath .githooks
git remote set-url origin https://cintelis@github.com/cintelis/stein-chain.git
```

### How it is enforced

| Layer | What it checks |
|---|---|
| `.githooks/pre-commit` | The identity git is about to commit with, and no control characters in staged text files |
| `.githooks/commit-msg` | The message credits no one else |
| `.githooks/pre-push` | The whole history being pushed |
| CI job **Contributor identity** | Every commit on `main` and on every pull request branch |

All four run `scripts/check-identity.sh`, which holds the expected identity in one place (shared with Sigilant). Never bypass the hooks with `--no-verify`.

## Orientation

Stein Chain is a post-quantum layer-1 blockchain (token: STEIN). Read before changing anything structural:

- `docs/SPEC.md`: protocol, security requirements, measured performance, roadmap.
- `docs/SHARD-READY.md`: invariants every protocol change must keep. Check any new transaction type against I-1 and I-2.

## Rules of the codebase

- **Post-quantum only.** No classical signature or key exchange, no second ML-DSA implementation. FN-DSA exists only behind stein-crypto's `fn-dsa-experimental` feature, for the FN-DSA test network (SPEC §3.5): never in a standard build, never for validators, never for mainnet. `scripts/check-crypto-policy.sh` enforces it. CI tests both builds.
- **Consensus code never panics and never wraps.** Use checked arithmetic; clippy's `arithmetic_side_effects` is on. `unsafe_code` is forbidden.
- **Everything hashed or signed is Borsh-encoded**, with a BLAKE3 derive-key context of its own.
- **Validators verify everything.** Never take a proposer's claim on trust; a block without witnesses is rejected.
- Before pushing, run what CI runs: `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo test --workspace --locked`, `bash scripts/smoke-devnet.sh`.
